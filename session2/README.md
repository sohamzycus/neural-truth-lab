## What is the assignment?

Design **one** BPE tokenizer (≤10,000 tokens) for four frozen Wikipedia *India* articles (English, Hindi, Telugu, Bengali). For each language:

`X = encoded_tokens / word_units`

Maximize `Score = 1000 / (X_max − X_min)` subject to English X ≤ 1.2.

## What did SamaBPE build?

A deterministic single-vocabulary BPE tokenizer with five benchmarked training strategies, score-aware optimization (English-seeded bootstrap + greedy merge selection), independent verification, grapheme integrity analysis, vocabulary ROI, and a static React lab UI.

## Why does token fairness matter?

If the same meaning needs twice as many tokens in one language, that language pays roughly twice the compute cost and fits half the content in the same context window.

## What is technically unique?

- **Score-directed optimization** — merge candidates ranked by impact on the assignment objective (fairness gap), not frequency alone.
- **English-seeded vocabulary** — 7,500-token English bootstrap keeps X_EN ≤ 1.2 while Indic-weighted continuation balances the gap.
- **One tokenizer proof** — mixed-script input encodes through the same merge table; no language routing.

## How does the tokenizer work?

1. Frozen Wikipedia corpora (NFC-normalized)
2. Whitespace pretokenization → UTF-8 byte-level BPE merges
3. Strategy search (shared, weighted, allocated, grapheme-aware, score-directed)
4. Winner exported as `results/tokenizer.json`
5. Independent verification recalculates all metrics

## Is it truly one tokenizer?

Yes. One `tokenizer.json`, one merge table, one encode path for all scripts. Tests: `python/tests/test_single_tokenizer.py`, `python/tests/test_parity.py`.

## How is X calculated?

NFC normalize → split on Unicode whitespace → discard empty segments → count word units. Encode full article with the final tokenizer. See [docs/DENOMINATOR.md](docs/DENOMINATOR.md).

## How is the score calculated?

Sort X_EN, X_HI, X_TE, X_BN. `Score = 1000 / (max − min)`.

## Limitations

- Official denominator is Unicode-whitespace word units (punctuation-aware sensitivity shown in UI, not scored).
- Score-directed optimization is Level C/D hybrid (English seed + greedy score-ranked merges), not pure from-scratch merge search.
- Browser grapheme display uses `Intl.Segmenter`; BPE encode matches Python for whitespace pretokenization.
- Rejected-merge graveyard empty when optimizer accepts all evaluated candidates.
